## Requirement

The AuthN backend ships enrol / verify / consume / recovery / status
endpoints + per-tenant policy + the `mfa` block on `/auth/me`. **A
user can't do anything with it without a UI.** This feature gives
them:

1. An **enrollment flow** on their own profile page: enroll → QR
   code + secret → first-TOTP → recovery codes shown exactly once.
2. A **nag banner** at the top of every page when the tenant's MFA
   policy requires MFA AND the user is still inside the grace
   window AND hasn't enrolled.
3. A **consume prompt** that fires automatically when a sensitive
   action (e.g. `POST /deals/{id}/approve`) returns `403 MFA_REQUIRED`
   — modal, ask for TOTP code, call `/auth/mfa/consume`, retry the
   original action with the new bearer.

**Constraints:**
- Must not break any existing page or flow. The backend is default-off
  (`policy_mode: "off"`), so default behaviour is: no banner, no
  consume prompt, no observable change to today's UI. The only new
  surface is the user profile MFA section — invisible to users who
  never navigate there.
- Must follow the Fusion AI-assisted engineering approach — plan
  first, phases with Done-when per phase, isolation (D-03), API-only
  data access, types from the backend contract.
